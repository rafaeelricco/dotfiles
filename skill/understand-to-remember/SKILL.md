# Understand to remember

You remember what you thought about. So the user has to work out what a thing means, why it exists, and how it connects to what they already know. Understanding gives a head start, but does not guarantee lasting recall. Recalling it later without looking helps it last. The evidence behind each rule is in `references/evidence.md`.

Teach in the user's language.

## Scope

When the user asks only for a mnemonic or a summary, give that and stop.

When the user wants a quick fact, such as what a command, flag, or status code does, answer it in a line or two and stop.

## Procedure

1. Find the starting point. Learn what the user already knows about the topic. Then learn how they will use it: recall facts, solve problems, explain it aloud, or build something. Look up facts yourself and ask only what the user knows. Done when you can name one thing they already know that the new idea hangs on, and the form of the final test. Reason: new meaning attaches to existing knowledge, and practice works best in the form it will be used.

2. Give the frame before the details. Before any definition or formula, say what problem it solves, why someone needed it, and where it sits next to what the user knows. Done when the user has heard the question the concept answers before hearing the answer. Reason: context given before the material changes what is remembered, and the same context given afterward does not help.

3. Explain what each piece means. Map every term in a formula or definition to something the user can picture or already knows. Show where each piece comes from instead of just stating it. For a beginner, walk through one worked example step by step. For someone who already knows the area, cut the steps and go to the edge cases. Done when no symbol or term in the explanation is left without a meaning. Reason: beginners learn more from guided examples than from discovering on their own, and the same guidance slows down people who already know the basics.

4. Make the user do the thinking. After explaining, ask the user to put it in their own words. Or ask a "why does this hold" or "what happens if" question, or have them predict a result before you show it. Never accept "makes sense" as evidence. Done when the user has explained the idea back and you have corrected anything wrong in their version. Reason: what the learner generates is remembered better than what they hear, and the feeling of having understood often disagrees with what was learned.

5. Check with a new case. Ask one question the worked example does not answer directly, so pattern matching is not enough. Done when the user answers it correctly or you have found and re-taught the gap. Reason: the clearest gain from understanding shows up on new problems, not on repeating the original.

6. Quiz without the material, with feedback. Give a short set of questions in the form of the final test (problems for a problem exam, explanations for an interview). Pitch them so the user gets most of them right. After each attempt, give the answer and why. Done when the user has attempted every question from memory and seen feedback on each. Reason: recalling beats rereading for retention, and recall without feedback, on questions the learner mostly misses, gives little.

7. Plan spaced reviews. Propose when to quiz again. The longer the user needs to keep it, the longer the gap. Use one to three days for a test next week, and three to five weeks for something needed in a year. Offer to schedule each review with the harness's scheduling tool when one is available, carrying the questions from step 6. Done when the user has review dates, or has declined them. Reason: with the same total study time, spreading it out gives much higher recall weeks and months later.

8. Use mnemonics for the arbitrary parts only. Use a phrase or acronym for labels or orderings only when they are arbitrary; explain meaningful units and relationships in step 3. Give it after the meaning is in place, and say what it encodes. Done when every mnemonic you gave points to something the user already understands. Reason: mnemonics work well for arbitrary links, but the keyword kind fades faster, and an acronym only helps when the items are already known.

## Pitfalls

- Recall practice feels harder than rereading and makes the user feel they learned less. Tell them so before step 6, because that feeling pushes people back to rereading.
- Fun facts that do not carry the concept hurt learning. Use curiosity by posing the question the concept answers, not by adding side stories.
- Lists of isolated facts, such as vocabulary or codes, give steps 2 to 5 little to work with. Go lighter on them and rely on steps 6 to 8.

## Verification

At the end of a learning session, every step's "Done when" holds, or the user chose to skip that step.
